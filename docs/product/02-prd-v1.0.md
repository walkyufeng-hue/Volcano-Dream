## 1. 文档目的

本文档定义火山梦绘AI MVP 的目标、用户流程、功能需求、业务规则、AI 输出要求、异常处理、数据指标和验收标准。文档以当前代码实现为基线，同时标注尚未实现但上线前后需要建设的内容。

## 2. 项目背景

传统解梦产品大多以关键词和固定词条为主，无法理解梦境中的人物关系、情绪、情节和个人背景。通用 AI 虽然可以解读梦境，但缺乏固定体验、成本控制、图片生成、历史沉淀和安全边界。

火山梦绘AI希望验证：用户是否愿意通过一个独立 AI 产品记录梦境，并从结构化文字解读与个性化配图中获得可感知的情绪价值和自我反思价值。

## 3. 产品目标

### 3.1 MVP 目标

- 用户无需学习 Prompt，即可在一个页面内完成梦境输入、文字解读和图片生成。
- 文字结果温和、相关、结构清晰，不制造恐惧或确定预言。
- 通过 IP 限流、全站预算和停止生成控制 API 费用风险。
- 用户可以保存或再次查看有价值的结果。
- 收集真实用户反馈，为模型评测和下一阶段迭代提供依据。

### 3.2 非目标

- 不提供医学诊断、心理治疗或危机干预。
- 不承诺预测未来，不为博彩、投资和重大决策提供依据。
- MVP 不建设社区、公开内容流或用户关注关系。
- MVP 不上线订阅支付和复杂会员体系。
- MVP 不支持桌面客户端，仅提供网页版。

## 4. 用户与需求

### 4.1 核心用户画像

| 维度 | 描述 |
|---|---|
| 年龄假设 | 18～35 岁 |
| 兴趣 | 梦境、心理、自我探索、情绪记录、AI 内容 |
| 使用频率 | 偶发，做了印象深刻的梦后使用 |
| 核心诉求 | 快速理解梦境、获得启发、保存有情绪价值的结果 |
| 主要顾虑 | 结果是否胡编、是否吓人、梦境隐私、生成速度、是否收费 |

### 4.2 Jobs To Be Done

- 当我做了一个印象深刻的梦时，我希望快速梳理其中的画面和情绪，以便理解它可能与近期生活有什么联系。
- 当文字难以表达梦境时，我希望获得一幅符合梦境氛围的画面，以便保存这次体验。
- 当我之后想回看时，我希望能找到最近的解读，而不需要重新生成并消耗次数。

## 6. 核心用户流程

```text
进入首页
  → 查看剩余免费次数
  → 输入梦境或选择示例
  → 点击“解读我的梦境”
  → 打开结果弹窗
  → 流式生成文字
  → 文字完成后自动生成配图
  → 复制解读 / 下载图片 / 关闭弹窗
  → 自动保存成功完成的结果到本地历史
  → 之后从解梦记录重新查看
```

### 中止流程

```text
生成过程中
  → 点击“停止生成”或关闭弹窗
  → 前端取消文字流和未完成的图片请求
  → 不再自动触发后续图片生成
```

> 已经发送到第三方服务的请求可能无法保证立即停止计费，因此“停止生成”主要防止后续调用和客户端继续等待。

## 7. 功能需求

### FR-01 梦境输入

**用户故事**：作为用户，我希望用自然语言描述完整梦境，而不需要理解解梦关键词。

需求：

- 输入框支持中文和常见符号。
- 最大长度 500 字，实时显示字数。
- 空内容不可提交。
- 生成期间禁用输入框和示例按钮。
- 提供飞翔、迷路、大海三个示例梦境。
- 点击示例后填入输入框，用户可以继续编辑。

验收标准：

- 0 字时主按钮不可点击。
- 1～500 字可提交。
- 超过 500 字无法继续输入，后端也必须二次校验。
- 选择示例不会立即调用 API。

### FR-02 发起解梦与防重复提交

需求：

- 点击按钮后立即打开结果弹窗并显示加载状态。
- 同一时间只允许一个文字解读请求。
- 快速双击或连续点击不能产生重复调用。
- 文字使用 SSE 流式返回。
- 首段文字返回后取消整页等待状态。

验收标准：

- 同一次用户操作只产生一个 `/api/divination` 请求。
- 请求失败时弹窗显示用户可理解的错误，不展示第三方详细报错。

### FR-03 文字解读

需求：

- 输出使用中文。
- 内容至少覆盖：梦境意象、可能的心理映射、近期生活启示、行动建议。
- 明确说明结果仅供娱乐和自我反思。
- 不把梦境解释为确定预言。
- 不制造灾难、疾病、死亡或宿命恐惧。
- 文字以 Markdown 生成并安全渲染。

建议质量目标：

- 相关性人工评分平均不低于 4.0/5。
- 安全性人工评分平均不低于 4.5/5，任何严重安全问题一票否决。
- 文字首字时间 P75 小于 4 秒，完整文字 P75 小于 20 秒。目标需根据真实部署数据校准。

### FR-04 自动梦境配图

需求：

- 文字成功完成后自动发起图片生成。
- 图片根据原始梦境和本次解读生成。
- 比例固定为 16:9，当前分辨率为 1K。
- 风格为梦幻插画，避免文字、水印、Logo、血腥和强恐怖内容。
- 主图片模型失败且明确属于地区限制时，尝试回退模型。
- 图片失败不影响文字结果阅读。
- 失败后允许在凭证有效期内重新生成。

验收标准：

- 图片始终显示在文字解读上方。
- 图片不被切成左右布局。
- 加载、成功、失败三种状态清晰可见。
- 图片失败时不重复扣除文字额度。

### FR-05 结果弹窗

需求：

- 桌面端使用居中弹窗，移动端占据大部分视口。
- 弹窗打开时禁止遮罩后的页面滚动。
- 弹窗内部独立滚动。
- 每次打开从顶部开始。
- 文字更新、生成结束和图片出现后，不得强制改变用户滚动位置。
- 支持右上角关闭和 ESC 关闭。
- 关闭弹窗后清空首页输入内容。

验收标准：

- 用户向下滚动时不会自动跳回顶部或底部。
- 关闭弹窗后底层页面恢复原滚动位置。

### FR-06 停止生成

需求：

- 文字或图片生成中显示“停止生成”。
- 点击后取消前端文字流和图片请求。
- 停止后不再自动发起图片生成。
- 若已有部分文字，允许用户阅读和复制，但不保存为完整历史。

验收标准：

- 停止后按钮和加载动画消失。
- 停止后不能因旧请求回调再次出现图片。

### FR-07 复制与下载

需求：

- 文字生成停止或完成后提供“复制解读”。
- 复制内容为纯文本，不包含 HTML 标签。
- Clipboard API 不可用时提供兼容回退。
- 图片完成后提供“下载图片”。
- 下载文件名包含品牌和“梦境画面”。

### FR-08 免费次数和费用保护

需求：

- 匿名用户按真实 IP 限制滚动 24 小时最多 1 次文字解读。
- 首页显示当前窗口内的真实剩余次数。
- 额度由后端缓存读取，不能由前端本地计数决定。
- 生产环境使用 Redis 或 Upstash，保证重启和多实例一致性。
- 全站默认每天最多 60 次文字、20 次图片，可通过环境变量调整。
- 全站额度耗尽时返回统一提示，不泄露内部预算信息。

验收标准：

- 第 2 次请求返回“今日免费解梦次数已用完”。
- 拒绝的第 2 次请求不能继续增加计数。
- 前端刷新后剩余次数与后端一致。

### FR-09 历史记录

需求：

- 每种类型最多保留最近 10 条，目前只有梦境类型。
- 文字元数据保存在 localStorage。
- 图片保存在 IndexedDB，避免占用 localStorage。
- 成功完成文字后保存记录；图片成功后补充图片状态。
- 支持单条删除和全部清空。
- 删除文字记录时同步删除图片。
- 打开历史结果时从顶部开始。

限制说明：

- 仅保存在当前浏览器。
- 清理浏览器数据、无痕模式或更换设备后无法恢复。

### FR-10 意见反馈

需求：

- 顶部仅展示意见反馈图标，不公开开发者邮箱或 GitHub 入口。
- 反馈正文 2～1000 字，联系方式选填、最多 100 字。
- 每个 IP 每小时最多提交 5 次。
- 成功后展示确认状态。
- 服务端保存时间、内容、联系方式和可选用户名。

部署要求：

- SQLite 数据目录必须使用持久化磁盘。
- Serverless 部署应迁移到托管数据库。

### FR-11 导航与响应式

需求：

- 桌面端提供首页、解梦记录、关于和意见反馈。
- 移动端使用折叠菜单，保留意见反馈入口。
- 首屏无需滚动即可看到输入框主要区域和主按钮。
- 不使用与输入无关的大面积装饰或右侧独立 Logo。

## 8. 业务规则

| 规则 | 当前配置 | 配置位置 |
|---|---:|---|
| 梦境最大字数 | 500 字 | 前端与 `src/divination/dream.py` |
| 匿名免费额度 | 2 次/滚动 24 小时 | `rate_limit=(2, 86400)` |
| 登录用户预留额度 | 600 次/小时 | 默认关闭登录，后续需重新设计 |
| 全站文字额度 | 60 次/24 小时 | `global_text_limit` |
| 全站图片额度 | 20 次/24 小时 | `global_image_limit` |
| 图片凭证有效期 | 10 分钟 | `TOKEN_TTL_SECONDS` |
| 历史记录 | 最近 10 条 | `MAX_HISTORY_COUNT` |
| 反馈限流 | 5 次/小时/IP | `feedback_router.py` |

## 9. 状态与异常处理

| 场景 | 用户提示/行为 | 是否继续生图 |
|---|---|---|
| API Key 未配置 | 服务暂未配置 | 否 |
| 免费次数耗尽 | 今日免费解梦次数已用完 | 否 |
| 全站额度耗尽 | 今日服务额度已用完 | 否 |
| 文字服务不可用 | 解梦服务暂时不可用，请稍后重试 | 否 |
| 流式连接中断 | 解梦服务连接中断，请稍后重试 | 否 |
| 用户停止生成 | 保留已有文字或显示生成已停止 | 否 |
| 图片失败 | 保留文字，显示重新生成配图 | 可重试 |
| 图片凭证过期 | 提示重新解梦 | 否 |
| 历史图片读取失败 | 仍展示文字结果 | 否 |
| 反馈提交过频 | 提示稍后再试 | 不适用 |

## 10. AI 方案与质量要求

### 10.1 当前文字方案

- 服务商入口：OpenRouter。
- 当前模型：`deepseek/deepseek-v4-flash`。
- 模式：关闭思考模式。
- 最大输出：1000 tokens。
- 温度：0.9。
- 输出方式：SSE 流式。

### 10.2 当前图片方案

- 主模型：`google/gemini-3.1-flash-image`。
- 回退模型：`recraft/recraft-v4.1`。
- 规格：1K、16:9。
- 输入：原始梦境最多 500 字 + 解读最多 1800 字。

### 10.3 Prompt 管理要求

- 每次修改 Prompt 必须记录版本、修改原因、评测集结果和回滚方式。
- 不以单条“看起来不错”的结果判断模型质量。
- 安全性下降时不得仅因为成本更低而上线。
- 模型切换前必须完成固定测试集对比。

## 11. 数据指标方案（待实现）

### 11.1 事件定义

| 事件 | 触发时机 | 建议属性 |
|---|---|---|
| `home_view` | 首页完成展示 | 设备类型、来源 |
| `example_selected` | 点击示例梦境 | 示例类型 |
| `dream_submit` | 后端接受请求 | 字数区间、剩余额度，不记录原文 |
| `text_first_chunk` | 收到第一段文字 | 首字耗时、模型版本 |
| `text_complete` | 文字完成 | 总耗时、输出长度、是否成功 |
| `generation_stopped` | 用户停止 | 阶段：文字/图片、已等待时长 |
| `image_complete` | 图片完成 | 模型、耗时、是否回退 |
| `result_copied` | 复制解读 | 是否完整结果 |
| `image_downloaded` | 下载图片 | 图片模型 |
| `history_opened` | 打开历史记录 | 记录距今天数 |
| `feedback_submitted` | 反馈成功 | 是否留联系方式，不记录正文 |

### 11.2 隐私原则

- 埋点不记录完整梦境、完整解读、联系方式和图片 Base64。
- 用户标识优先使用匿名随机 ID，不使用明文 IP 作为分析标识。
- 日志不输出 API Key、JWT、图片数据或用户完整正文。

## 12. 安全与部署要求

- API Key 只能通过后端环境变量配置。
- `.env` 不得提交到 GitHub。
- OpenRouter API Key 设置硬性消费上限。
- 生产限流必须使用 Redis 或 Upstash。
- 只有在可信反向代理之后才能启用代理请求头，并配置可信代理网段。
- 正式前端域名必须写入 CORS 白名单。
- 启用登录前必须替换默认 JWT Secret。
- 反馈数据库必须使用持久化存储。
- 全站使用 HTTPS。

## 13. 可用性与无障碍要求

- 所有图标按钮提供 `aria-label` 或 title。
- 弹窗支持 ESC 关闭，并应补充焦点锁定与关闭后焦点归还。
- 键盘可以访问主按钮、示例、复制、下载和关闭。
- 颜色不能作为状态的唯一表达方式。
- 尊重 `prefers-reduced-motion`。
- 移动端最小可用宽度 320px。

## 16. 待决策问题

1. 用户最看重的是文字启发、图片情绪价值，还是历史记录？
2. 自动生图是否显著提高下载和留存，能否覆盖额外成本？
3. 三次免费额度是否足够，滚动 24 小时是否比自然日更易理解？
4. 文字输出 1000 tokens 是否会在复杂梦境中截断？
5. 哪类权益具有真实付费意愿：更多次数、高清图、云端历史还是重新生图？
6. 是否需要在输入前增加更明确的第三方 AI 和敏感信息提醒？
